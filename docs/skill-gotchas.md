# Skill gotchas

One line per gotcha: the skill reference it belongs in, then the fact.

- references/platform-snes.md (fixed one-glyph-a-cell fields: name tags, labels): no runtime VWF needed: render each English string proportionally at build time into its cells and give every distinct cell bitmap a spare glyph code (dedupe; centre to whole cells, not pixels, or every label gets unique cells). Check the game's glyph-offset formula for 16-bit truncation: here codes past 0x071F wrapped below the hook's "English" threshold, capping the spare codes at 544.

- references/platform-snes.md: `snes_romreads.lua` prints `off` with the LoROM formula; on HiROM games read the file offset as `addr & 0x3FFFFF` (the probe header says so, the log column misleads).
- references/pipeline.md (§Recon): `tbl.py` is byte-greedy; with 16-bit LE codes and `FFxx` control words it decodes `FF FF 00 00` as `[FF]`+`FF00` and desyncs. Tokenise word by word in the extractor (roundtrip still holds).
- references/graphics.md (§Survey): a 512 KB-per-sheet whole-ROM render is unreadable noise; sweep at 32-64 KB per sheet.
- references/graphics.md (§Survey): graphics need not start 16-byte aligned (this game's chapter-card glyphs sit at 0x18449A); an aligned 2bpp sweep shows them as noise. Score each 4 KB block for row-to-row agreement at every even phase, keep only tile-like blocks and render each at its best phase (`tools/gfx_map.py` + `tools/gfx_sweep_map.py`): 1 MB of candidates in 34 readable sheets instead of 48 unreadable ones. Worth a skill script.
- references/pipeline.md (§Recon): text blocks can start at odd file offsets (0x280F25 here); any "is this 16-bit text" test must try both byte parities.
- references/pipeline.md (§Recon): to get a script VM's argument counts fast, list each handler's `STA <script offset>` sites with the 3-4 instructions before them (`INC A`x2, `ADC #n`), then confirm by tokenising every message and counting opcodes; handlers that rewind the pointer (`DEC A`x2) are printable name macros, not codes.
- references/emulator-qa.md (§Debug tool): before building warps by hand, look for an unreferenced debug select: grep the ROM for ASCII like `SCENARIO`/`STAGE`/`MAP` near a list of `NN:` labels. Here one RTL-continuation write (`$00EB` = C0:D8B8) opens the developers' scenario select, and its confirm path enters every scenario the game's own way (briefing, card, map).
- references/emulator-qa.md (§emu.py): emu.py with no `--frames` and no route stops at frame 0 (route_done is true at once); a warp script that queues its own presses with `L.press` needs `--frames`. And `--mash` starts at frame 0 when there is no route, so a warp must queue its own mash after the warp, or the mash drives the title menu first.
- references/emulator-qa.md (§emu.py): Mesen's Lua working folder is not always `tools/mesen` (here a relative `../debug/scenes.tsv` failed); derive the repo root from `OUT` (`OUT:match("^(.*)/work/")`) or pass absolute paths through `--var`.
- references/emulator-qa.md (§Debug tool): some menus take one cursor move and then ignore further presses at any gap (this town menu); routes that need a second Down are flaky. Poke the cursor variable instead of pressing.
- scripts/sheet.py: `is_blank` takes the tuple from `read_png`, not a path (easy to misuse from a helper).
- references/emulator-qa.md: under Claude Code's context-mode, a Read or command output over ~4 KB comes back as a stub; write tool output to a file and Read it with offset/limit (even 60-line disassemblies hit this).
- references/emulator-qa.md (§Text coverage / Hooks): a region-read probe (first read of each byte in given ranges, with PC; tools/lua/regionreads.lua here) run over the whole warp scene list confirms side-table readers in one pass; worth shipping beside textcover.lua, which logs no PC.
- references/pipeline.md (§Repo layout): Python write_text on Windows writes CRLF; pass newline="\n" when dumping script JSON or git warns and diffs churn.
- references/pipeline.md (§Recon, code = font cell): shape-matching an 8x16 hand-squeezed kanji font against MS Gothic is near useless (true kanji ranked 40-1000+); budget a context-led visual pass instead.
- references/platform-snes.md (§Engine patching): when the English font is laid out like the game's font and placed where the game's own 16-bit glyph-offset formula lands for the new code range (here $FF:E400 for codes $0F20-$0F7F, base $FF:0000), every fixed-cell drawer that computes a JP glyph address needs only a base-pointer hook, not its own English path.
- references/emulator-qa.md (§Visual QA): `codex exec -i a.png -i b.png "prompt"` treats the prompt as another image (`-i` takes many values) and then waits on stdin; pass the prompt on stdin (`codex exec -i a.png ... < prompt.txt`).
- references/pipeline.md (§Marker): a fixed-record split with the wrong lead offset still roundtrips (identity and coverage tests pass); here the speakers table was 2 words off for a whole phase. Have the extractor's test check that a known name lands at the start of its record.
- scripts/lua/probes/snes_romreads.lua: logs one line per distinct (PC, bank), so a string loop shows only its first read (the file-menu strings looked unread); to find a table, watch.lua on the suspected range or log per address.
- references/pipeline.md (§Extract): a word-encoded region that starts on an odd byte roundtrips fine but splits even-phase strings into nonsense marked data (the file menu here); check every pointer target's parity against the region start.
- references/pipeline.md (§Extract): a counted-string area can flip word phase several times (odd-length layout records between strings); an extractor that silently skips off-phase pointer targets loses those strings (18 here, incl. the status labels). Split by pointer targets, let one file span several phase segments, and test that every pointer target has an entry.
- references/pipeline.md (§Marker): grid strings (one string drawn into tile slots, shown as tilemap slices) need a per-cell marker (a fixed-width code per cell, here 6-px char + 2-px mark = 8 px); a continuous filler shows only mid-text fragments, so no slice can be measured or identified.
- references/translation.md: assets/batches.py merge writes json with indent=1 and adds a 'status' key; fine here, but a repo with its own write_file should use it. Dialogue with structural quote words (「」 kept as codes) fits the 'author paragraphs, generate lines' model well: tools/pages.py here wraps per JP box and adds {next} boxes.
- references/translation.md: a batch whose bNNN.new.tsv has one row missing its tab makes tl_reuse fill crash, and if nobody notices the batch is never merged (b038 sat unmerged for a session): after each session, scan for bNNN.tsv with no bNNN.out.tsv, and count empty en per file.
- references/pipeline.md (§Extract): side tables that are engine scripts need that engine's opcode argument counts in the decoder; without them argument words decode as text (here 0x0000 after FF09 showed as a fullwidth space, FF14's 0x0002 as 、) and translators drop or mangle them.
- references/pipeline.md (§Insert): side-table scripts that grow need not have their pointers found: if the script VM has a jump (here engine B's indexed jump FF0B via a 3-byte table), leave a jump in the old slot to a copy in free space and jump back to the next entry; then split the table at every pointer target its own scripts use (incl. jump tables) so nothing lands inside a trampolined entry. A 24-bit pointer scan alone gives hundreds of false hits in a 4 MB ROM.
- references/platform-snes.md (C1/grid strings): a TAB that rounds floor(px/8)*8+8 wastes a cell whenever the last glyph's blank spacing column crosses an edge, and a chain of TABs costs a word per cell: round ceil((px-1)/8)*8 instead (spacing may spill 1 px) and add a 2-word "set cell" code for long gaps; then 3-letter labels fit 2 cells and the string keeps its JP word count. Lay out with a tool (here tools/grid.py) and check it in batches, not by hand.
- references/emulator-qa.md: a savestate made on an older build keeps that build's text tiles in VRAM; a dialogue box then shows old and new text overlapped (looks like a wrap bug). Re-make states (warp_all --states) after every text build before reading shots from them.
- references/platform-snes.md (VWF): when two text paths (dialogue VWF and a menu-string VWF mode) share one pixel-cursor variable, the second must save and restore it; the dialogue's "has the engine moved the cursor" test (cursor == last value written) can match by chance (0 after a cold boot), and the next box then starts at the menu's pixel offset (here: tavern line began at the right edge).
- references/emulator-qa.md (emu.py, skill fix candidate): every Mesen run leaves a ~95 MB `_mesen` copy of the emulator in its `--out` dir and never removes it; 1375 of them (~65 GB) filled the C: drive and warp_all scenes then died with `WinError 112` (reported as scene failures). emu.py should delete `_mesen` after the run (or hardlink); until then `find work -name _mesen -prune -exec rm -rf {} +` after tours.
- references/pipeline.md (text that ends on a quote): a printer can use the closing quote as its end-of-message test (Bounty Sword C6:DDE7 stops only when a line ends in 」/』); translating 『Title』 as 'Title' with ASCII quotes made the card printer run on into the next message. Keep the game's closing-quote code in such strings and lint it.
- references/emulator-qa.md (emu.py): `--var SHOTS=...` is refused ("use NAME=LUA with a non-driver global name"): SHOTS is an emu.py driver global; name probe flags otherwise (MSGSHOT).
- references/pipeline.md (Extract/QA): a phase-1 scan missed a 5-word record table in a code bank (town menu, C3:96B2) and a dozen prompt strings just outside extracted regions; run `jp_left.py --orig` on the build at the start of phase 8 and diff it against the region list, not only at release.
- references/pipeline.md (Extract, script VMs): opcodes with odd-sized arguments (here engine A FF25/FF27/FF29/FF2A = 3-byte address, FF26 = address + 24-bit jump) flip the text's word phase; a word-aligned extractor stops at the first one and files the rest as data. Before cutting a script region, read every opcode handler's argument size and tokenise byte by byte where any is odd; also sweep the whole ROM for scripts by opcode structure (start opcode .. end opcode, all tokens valid), not only for kana runs.
- references/pipeline.md (Relocation): a script that ends in a "wait, then run on into the next" code (FF03) must move together with what follows it; relocating it alone made it run into unrelated bytes. Group scripts into units up to a real end code, extended while any jump in the unit targets a later script.
- references/platform-snes.md (VWF): a script opcode that prints a RAM buffer word by word (FF29 item name) bypasses the menu VWF's packed-pair decoding; English names packed two letters a word print as garbage there unless that loop is hooked too. To call a game routine that ends in RTS (here the hooked glyph draw) from bank $FF code, push PBR + return-1, push (address of an RTL byte in the routine's bank) - 1, then JML in.
- references/pipeline.md (dump refresh): a refresh that keeps any old key the new split lacks carried a stale caller list (`refs`, a false 24-bit match into code) onto a re-split entry; the relocation would have rewritten those 3 bytes of code. Treat refs as extraction output and never carry them over.
references/emulator-qa.md: a 'msg' warp with MSGPTR at an FF0A-0000 (battle-map) engine A prompt draws no box outside battle context; prove such prompts in a battle scene instead.
